## Windows

Jobs 101231926117 and 101231926247 fail before TCP test execution. Stock Jolt
v0.8.1 (`51f10a0239096f804a6017f850b7b235ebe40168`) attempts to slurp a path
of the form `D:\repo/D:\repo/deps.edn`. Its `project-relative` in
`host/chez/java/io.ss` recognizes only leading slash paths as absolute.
The dependency resolver's `abspath` has a separate equivalent limitation.

Upstream PR https://github.com/jolt-lang/jolt/pull/710 has since been rebuilt
from refreshed main `05b573a98e4b834e65e924d69d84df53a94b771f`.
Candidate `f7f5dd31251e0b04dc4f8f377a7779f89b932379` changes both the
dependency resolver and host I/O path classification, with a separate
rooted-but-non-absolute Windows File path.
It is ready for upstream review after hosted validation.

A runtime-relative JOLT_PWD workaround was explored and withdrawn before
publication: `project-relative` would prefix `..` again. A PowerShell helper
unit check did not establish full runtime correctness. Both released 0.7.28
and 0.8.1 contain the same leading-slash host predicate; the failure is not
evidence of a regression introduced between those releases.

The refreshed candidate passes 65/65 dependency-expansion tests and 1657/1657
host-unit cases locally under Chez 10.4.1. Claude's final code and prose review
returned READY. Its first hosted Windows run, 33946201318 job 101252626217,
passed the 65 dependency cases and fixed the original doubled path, but the
new assertion incorrectly expected this source tree's fallback root to contain
`jolt-core`; actual output was `D:\a\jolt\jolt/src`. Because this repository
has no `deps.edn`, that check could also pass through a silent config miss.
Candidate `c6fb79a2b95fd1fe429a183eaba55c920f6c6406` replaces it with a
temporary project whose `deps.edn` declares a unique `marker-src`; stock code
falls back to `src`, while the fix must return the marker. Claude reviewed that
correction as non-vacuous. A new
hosted run, 33946800979 job 101254264204, returned the expected
`D:\a\_temp\absolute-path-project/marker-src`, proving the host-open and
dependency-root path. Its separate rooted-File expression then raised an
index-out-of-bounds error in the diagnostic `(subs user.dir 0 2)`. The next
candidate computes that expected drive root in PowerShell and leaves only
`File.isAbsolute`/`getAbsolutePath` under test.

Hosted run 33947276808 job 101255554219 again passed 65/65 dependency cases
and resolved `marker-src`. It exposed a separate PowerShell 5.1 argv boundary:
embedded quotes in the native `-e` argument were removed, so even a trivial
Clojure string literal failed during analysis before reaching `java.io.File`.
The final candidate constructs the same rooted path and environment-variable
name without string literals. The exact replacement returned `true` under a
local native Windows Chez 10.4.1 run, and Claude reviewed it as correct,
non-vacuous, and quoting-safe.

The jolt-tcp Windows x86_64 and ARM64 jobs are prepared to pin the final
reviewed candidate `f7f5dd31251e0b04dc4f8f377a7779f89b932379` from
`casselc/jolt`. Linux and macOS continue to exercise released Jolt v0.8.1, so
this preview does not replace released-runtime coverage. Upstream tests run
33947866847 passed both aggregate job 101257111669 and Windows dependency-path
job 101257111802; flake run 33947866809 passed Linux x86_64 and macOS arm64.
The downstream hosted result for this exact workflow revision is tracked on

not claim those TCP platform gates passed before publication.
